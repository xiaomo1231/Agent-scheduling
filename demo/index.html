团队与模型

      
给当前项目的每个岗位挑 agent 和模型。一个岗位可以同时挂两个 agent；只有一个 agent 时，协调者照样能拆任务、排顺序。

      
一键配置

      

        

          
每个岗位定两件事：谁来干（agent，负责动手改文件、跑命令）和用什么模型（agent 背后的大脑）。模型可以选分组里的某个用途，额度用完会自动切备用；也可以直接指定某个来源里的模型。

          

          
调研组的专门优化
            
  • 工具不同：开网页检索、网页转 Markdown、PDF 和表格提取、去重；关掉工作区、终端和改代码的权限。
    • 
            
  • 先定字段再抓：协调者先和你确认要收集哪些列，检索员按列抓，整理员只负责清洗合并。
    • 
            
  • 模型分工：抓取和整理吃上下文多，用便宜的长上下文模型；核查换另一家模型，避免同一个模型自己验自己；统稿用强模型。
    • 
            
  • 证据优先：每条数据带来源链接、抓取时间和原文片段；单一来源标“待核实”，互相矛盾的自动送到群聊评审的“中立调研”。
    • 
            
  • 进度看得懂：显示已收集 128 / 200 条、来源覆盖 14 个网站、待核实 9 条，而不是代码行数。
    • 
            
  • 产出：数据表（Excel / CSV）、来源清单、结论报告三份分开交付。

          
只有一个 agent 也能用协调者
            
  • 协调者照常拆任务、排先后、做验收，只是所有子任务都派给同一个 agent，按顺序一个个做。
    • 
            
  • 协调者可以由这个 agent 兼任（不多花钱），也可以单独用一个便宜模型来做（拆任务更稳，不占主力额度）。
    • 
            
  • 以后加 agent 不用重建项目，直接在上面表里加一行，协调者会把还没开始的任务重新分配。

        

        

          
接力：贵的模型出主意，便宜的模型干活

          
在设置里管理预设

          

          

          

          

        

      

      
“两个 agent 怎么配合”四种：分工（协调者按子任务分给两边）、主备（一个额度用完换另一个）、并行对比（同一任务两边都做，你挑一个）、写 + 审（一个写，另一个审，审不过打回）。两个 agent 各在自己的工作区，留痕里各有各的身份。

工作区与协作

      
这些选项决定 agent 在哪里干活、能碰什么、怎么交付。不确定就保持推荐值，每一项都写了开启后的效果和代价。

      

        

          
worktree 隔离推荐

          
给每个 agent 一份独立的代码副本（同一仓库的不同分支）。几个 agent 同时改代码不会互相覆盖，做砸了也只影响它自己那份。

          

          
代价：多占磁盘；做完要合并回主分支，偶尔需要处理冲突。

        

        

          
沙箱推荐

          
限制 agent 能碰的文件和网络。就算它执行了危险命令，损害也只会留在工作区里。

          

          
代价：越严越安全，但有些安装、联网命令会被挡住；容器模式需要先装 Docker。

        

        

          
策略约束

          
提前写好的规矩，agent 每次动手前先对照检查，违反就停下来问你。

          
    
            
    •

协作方式

          
agent 之间怎么说话。所有消息都会出现在通信总线里，你随时能看、能拦。

          

          
代价：直接对话更快但消息更多；只走协调者更可控，但协调者容易成为瓶颈。

需要连接 GitHub 账号。项目不在 GitHub 上时，只在本地生成分支。
