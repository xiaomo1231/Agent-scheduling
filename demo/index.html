需求评审：要不要做“记住此设备 30 天”

每个 agent 带着自己的记忆和角色发言。每个预设都有一个专门挑毛病的角色。结论由你拍板，或交给只看论据的决策者。

安

工作区与协作

      
这些选项决定 agent 在哪里干活、能碰什么、怎么交付。不确定就保持推荐值，每一项都写了开启后的效果和代价。

      

        

          
worktree 隔离推荐

          
给每个 agent 一份独立的代码副本（同一仓库的不同分支）。几个 agent 同时改代码不会互相覆盖，做砸了也只影响它自己那份。

          

          
代价：多占磁盘；做完要合并回主分支，偶尔需要处理冲突。

        

        

          
沙箱推荐

          
限制 agent 能碰的文件和网络。就算它执行了危险命令，损害也只会留在工作区里。

          

          
代价：越严越安全，但有些安装、联网命令会被挡住；容器模式需要先装 Docker。

        

        

          
策略约束

          
提前写好的规矩，agent 每次动手前先对照检查，违反就停下来问你。

          
    
            
    • 
            
    • 
            
    • 
            
    • 
          

          

          
代价：规则越多，agent 越常停下来等你。

        

        

          
协作方式

          
agent 之间怎么说话。所有消息都会出现在通信总线里，你随时能看、能拦。

          

          
代价：直接对话更快但消息更多；只走协调者更可控，但协调者容易成为瓶颈。

        

        

          
一键开 PR

          
任务做完后把分支推到 GitHub，开一个合并请求（PR）。你在网页上看每一处改动，确认后再点合并。

          

          
需要连接 GitHub 账号。项目不在 GitHub 上时，只在本地生成分支。
