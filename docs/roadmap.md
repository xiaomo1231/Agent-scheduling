# 路线图

## 已完成

- **v0.1 界面原型**：`demo/index.html`，单文件可点击原型，数据是演示数据。产品设计整理在 [design.md](design.md)。
- **v0.2 能跑的程序**（本版）：
  - 工程骨架：monorepo（core / server / web / desktop），TypeScript strict，vitest。
  - core：领域类型、事件 + 哈希链、共用 reducer、权限判断（命令解析、风险识别、白名单、指纹）、计划调整与自然语言解析、讨论串状态与自动解决规则、画布布局引擎、模型目录与思考挡位、Skill 通用模板（解析、转换、扫描、投放）、安全体检。
  - server：JSONL 事件日志（启动校验链）、加密密钥存储与打码、模型接入（Anthropic SDK、OpenAI 兼容、模拟）、审批队列（超时拒绝、指纹作废、“以后都允许”、审查模型）、运行器（内置 agent、官方 CLI、模拟）、协调者引擎（模型 / CLI / 规则三种大脑、双脑、备用）、Skill 安装服务、本地网关（127.0.0.1 + token + Host / Origin 校验 + CSP）、命令行入口。
  - web：首页、项目画布与编辑模式、协调者、讨论串（进行中 / 已解决、计划编辑、审批卡、撤销）、模型来源与分组、项目设置（协调者、双脑、默认模型、自动解决、说明）、权限与安全、Skills、留痕。
  - desktop：Electron 外壳，系统钥匙串加密密钥，窗口不给 Node 能力、不能跳出本地页面、拒绝所有权限请求。
  - 测试：89 个，含端到端（规则协调 + 模拟运行、模型协调 + 内置 agent 写文件、网关鉴权与事件推送、审查模式）。

- **v0.3 装上就能用**：
  - 安装包：electron-builder 出 AppImage / dmg / exe，打 `v*` 标签时 GitHub Actions 三个平台一起出包。签名和自动更新还没做（需要证书）。
  - 独立工作区：项目目录是 git 仓库时，每个讨论串在 `zhongshu/<讨论串>` 分支的 worktree 里干活；做完提交到分支，讨论串里出现“合并到 base / 丢弃”的卡片。没合并前不会自动解决。合并前会检查主目录干净、在 base 分支上，冲突就放弃合并并告诉你。
  - 用量与额度：每次 API 调用记 token（按天 / 项目 / 来源 / 模型累计），“用量”页按模型、项目、天看。碰到 429 时按 Retry-After（没有就 1 分钟起翻倍，最长 5 小时）等，恢复后自动继续；可以在项目设置里关掉。只记 token，不算钱（各家价格变化太快）。订阅账号走官方 CLI，用量看不到。
  - 子 agent：内置 agent 多了 `run_subagent` 工具，派只读子 agent（只能读文件、列目录、抓网页）去查资料，同一轮里多个并行，全局最多 3 个同时跑。子 agent 读过网页，它交回的结论也按外部内容处理，父 agent 之后跑命令要确认。
- **v0.4 记忆**：每个项目一页“桌面页”（≤ 4KB，每次都放进协调者和 agent 的提示词）加记忆条目（最多 500 条，按和当前任务的相关度挑 8 条带上）。协调者和 agent 有 `remember` 工具；你也能在“项目记忆”模块里加、删、置顶。每天自动整理一次（有新条目、距上次超过一天），用辅助模型合并重复、删过时的、更新桌面页；置顶的不让模型动；没有模型时只去重。记忆整段标成参考资料，和用户这次说的冲突时以用户为准。
- **v0.5 协作**：
  - 消息渠道：Telegram 双向（长轮询，不需要公网地址）：在中枢拿 6 位配对码，私聊机器人发 `/pair 码`；之后只认这一个聊天。收到待批准时带“批准 / 拒绝”按钮；直接发文字就是跟协调者说话，协调者的回复会转回来；`/status` 看进度。配对只能在私聊里做，码 10 分钟有效、猜错 5 次作废。飞书 / 钉钉 / 企业微信用群机器人 Webhook，只发通知，地址必须是官方域名。token 和地址加密存在本机。
  - 群评审：7 套班子（方案评审、代码评审、产品决策、写作润色、风险评估、技术选型、头脑风暴），每套都有一个唱反调的；讨论 1 到 4 轮，最后拍板模型给结论，贴回发起的地方。协调者可以用 `start_review` 自己发起。
  - 划词追问：在任何消息里选中一段文字，点“追问”开一个侧枝讨论串单独聊，不打扰原讨论串；聊完选“丢弃 / 带回结论 / 整段带回”。

- **v0.6 预设工作流与编排**（进行中）：
  - core `workflow/`：工作流定义（表单字段 + 五种节点 + 连线）、校验、拓扑排序、就绪节点、切批、CSV、四个内置预设。
  - server `flows/`：执行器。一次运行 = 一条 `kind: 'flow'` 的讨论串，节点投影成步骤；按依赖并行（最多 3 个）；人工检查点进待办收件箱，通过 / 附意见打回（上游模型节点重做，最多 3 次）；批量节点切批并行再合并；产出落到 `产出/<运行>/`。
  - server `search/`：博查 / Tavily / Brave 搜索服务，`web_search` 工具接上。
  - web：工作流台、待办收件箱、产出三个常驻窗口和“工作流模式”布局；编排编辑器（拖节点、连线、改参数、另存）；模型页的搜索服务设置。
  - 详见 [workflows.md](workflows.md)。
