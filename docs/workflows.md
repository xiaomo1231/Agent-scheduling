# 预设工作流与可视化编排

给非程序员用的那一层：选一个模板、填表、点开始，在待办收件箱里拍板，在“产出”里拿文件。完整的调研与取舍见项目里的方案文档；这里只写实现约定。

## 概念

- **工作流（FlowDef）**：一张图。`inputs` 是发起表单的格；`nodes` 是节点；`edges` 是有向连线。不分端口：下游节点自动拿到所有上游的输出。
- **运行**：一次运行就是一条 `kind: 'flow'` 的讨论串。节点在拓扑序上投影成步骤（步骤 id = 节点 id），所以讨论串列表、进度、停止 / 重试、Telegram 通知全部复用。运行信息挂在 `Thread.run` 上。
- **节点结果（NodeOutput）**：正文落在工作区 `产出/<时间>-<名字>/` 下的 `.md` / `.csv` 文件里，事件里只存路径、类型、前 300 字和 sha256。

## 节点种类（界面上的叫法）

| 叫法 | kind | 做什么 |
|---|---|---|
| 表单里的数据 | `input` | 把表单的文件 / 长文本字段变成表或文字给下游。粘贴的多行文本按 CSV 处理（没逗号就是一列） |
| 搜一搜 | `search` | 走搜索服务（博查 / Tavily / Brave），不走模型。查询词可写 `{{inputs.键}}`，也可以从上游表格的某一列取。输出带链接的表，标记为外部内容 |
| 让模型做 | `agent` | 一句“要它做什么”+ 自动附上表单输入和上游结果，复用 BuiltinRunner；工具按节点收窄（`StepTask.tools`）。`output: 'table'` 时要求模型用 ```csv 代码块输出并解析；`each: {rows}` 把上游表切批并行跑（最多 3 并行、每批 ≤ 200 行、≤ 50 批）再合并 |
| 等我确认 | `human` | 步骤置为 `wait`，进待办收件箱。通过：上游结果原样透传（`pick` 时只传勾选的行）；打回：必须写意见，最近的上游模型节点带着意见重跑，它之后的节点全部重置；一次运行最多打回 3 次 |
| 导出 | `export` | 把上游结果写成指定文件名 |

## 事件

`flow.saved` / `flow.removed`（用户自建的工作流；内置预设在 `core/workflow/presets.ts`，不进事件）、`thread.run`（运行开始）、`run.node`（节点状态 / 结果变化，reducer 同时改同编号步骤的状态；重新排队会丢掉旧结果）、`run.decided`（拍板）、`search.saved` / `search.removed`（搜索服务设置，key 在密钥库）。

## 命令

`flow.save`、`flow.remove`、`flow.start {projectId, flowId, inputs}`、`flow.decide {threadId, nodeId, approve, note?, picked?}`、`flow.retry`、`search.save {provider, key?}`、`search.remove`、`search.test`。读产出文件：`GET /api/run-file?thread=…&path=…`，只能读这次运行的目录。

## 安全

- 四个内置预设都不给 `run_command`。用户自建时勾了“跑命令”会看到提示，而且每条命令仍走现有审批。
- 搜索结果和网页都是外部内容：进模型前包 `<untrusted>`；读过外部内容的节点输出带 `external: true`，下游模型节点以 `externalContext` 启动，跑命令一律要确认。
- 模型节点的工作区就是这次运行的目录，读不到项目里别的文件；表单的文件字段只接受工作区内的路径，否则按粘贴文本处理。
- 模板变量只认 `{{inputs.键}}`，没有表达式。

## 前端

- 常驻窗口：`flows`（工作流台）、`inbox`（待办收件箱：检查点 + 卡住的节点 + 审批）、`outputs`（产出：查看 / 下载 / 用同样表单再跑）。布局预设“工作流模式”就是这三块。
- 编排编辑器 `#/flow/<id>?p=<项目>`：节点卡片拖动，从右边圆点拖到另一个节点连线，右侧改参数和表单字段；保存前跑 `validateFlow()`。内置预设只读，“复制一份改”另存。自己写的，没有缩放和小地图；节点超过十来个再考虑换 React Flow，数据模型不依赖编辑器。
