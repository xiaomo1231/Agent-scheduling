# 0003 工作流是图，运行是讨论串

日期：2026-11-03

## 背景

要给非程序员提供预设工作流（短视频热点选题、批量数据处理等），并且让他们能用“拖节点、连线”的方式改。v0.5 的讨论串只有线性步骤，步骤没有输入输出，也没有“等人拍板”这种非模型步骤。

## 决定

1. 工作流定义（节点 + 边 + 表单字段）放在 core 的 `workflow/` 模块，纯数据 + 纯函数（校验、拓扑、就绪节点、切批、CSV）。
2. 不另起一套引擎。一次运行就是一条 `kind: 'flow'` 的讨论串，节点状态投影成步骤；执行器 `server/flows` 和协调者并列，协调者不碰 flow 讨论串。
3. 节点间传数据走文件（运行目录），事件只存路径和摘要。
4. 模型节点复用 BuiltinRunner，只加了三个可选字段：`tools`（按节点收窄）、`externalContext`、`prompt`。
5. 人工检查点和命令审批同等地位，走同一个收件箱和同一套渠道通知。
6. 编辑器先自建（零依赖），数据模型不依赖编辑器。

## 后果

- 讨论串页面、停止 / 重试、worktree 之外的所有基础设施直接可用；flow 讨论串不开 worktree。
- 新增节点种类只需要在 core 加类型 + 校验，在 server 加一个 `runXxx`，在编辑器加一个表单。
- 边不分端口是对非程序员的简化，代价是下游拿到的上游顺序由连线顺序决定；需要精确路由时再加端口。
